# «Цветная мастерская» — план реализации

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Цель:** отдельная браузерная раскраска; выбрать цвет, заполнить им любую замкнутую деталь или вернуть ей белый цвет ластиком. Первый рисунок посилен на небольшом экране, остальные доступны сразу и постепенно детальнее.

**Архитектура:** четыре оригинальные SVG-сцены описаны данными, контроллер меняет только заливку выбранной области. Статическая сборка в один `index.html` работает локально и в подкаталоге; на сайте новый адрес `/raskraska/` и одна дополнительная карточка. Сохраняются рисунки и открытая сцена только под ключом `raskraska-v1`, без сервера, аналитики, зависимостей или подключения к прежним играм. Текущая задача — локальный предпросмотр, не публикация.

### 1. Закрепить игровой контракт

- `raskraska/test_browser.py`: запустить в Chromium изолированную HTTP-копию. Сначала проверить, что RED объясняется отсутствием игры, затем те же проверки должны дать GREEN. Основной цикл: выбор → одно нажатие → цвет только внутри контура → перекрашивание → ластик до белого → отмена. Нажатие на фон и до выбора краски ничего не меняет.
- Проверки по завершении: все четыре сцены и все области кликабельны, клавиатура и эмулированный тач работают, сохранение изолировано и переживает reload, повреждённое/недоступное хранилище не блокирует игру, скачанный HTML открывается без сети.

### 2. Нарисовать четыре листа

- Только `raskraska/src/scenes.json`: `[{id,title,areas:[{id,label,d,at:[x,y],color}],details:[d,...]}]`. Общий `viewBox="0 0 480 360"`. `d` — замкнутый SVG path у каждой области, `at` — неперекрытый центр нажатия; `color` — ключ палитры для обложки/превью, не для решения.
- `balloon` — «Воздушный шар» (5 областей), `house` — «Лесной домик» (8), `rocket` — «Ракета и планеты» (11), `sea` — «Подводный мир» (15). `details` — только неактивные линии, не выглядящие как дополнительные замкнутые области. Палитра: `red`, `orange`, `yellow`, `green`, `blue`, `purple`, `pink`, `brown`.
- Проверить рисунки на реальном размере и точки всех областей на верхний активный слой. Большие первые детали и закруглённый тёмный контур; позже больше самостоятельных маленьких деталей, но не требовать точности стилуса.

### 3. Собрать студию и каталог

- `raskraska/src/page.html`, `style.css`, `app.js`, `raskraska/build.py`: без сети и библиотек, 8 красок, крупный ластик, отмена последнего действия в текущем рисунке, подсказка «Выбери краску → Нажми на рисунок», четыре листа на выбор без блокировки. Белый незакрашенный цвет — `#fff`; после заполнения не блокировать редактирование и не менять рисунок автоматически.
- `python3 raskraska/build.py` создаёт `raskraska/index.html`; `--check` сравнивает сборку побайтно. `index.html` каталога получает только одну новую карточку перед заглушкой, оригинальная `raskraska.webp` — из графики игры. Все прежние пути/игры/сохранения остаются без изменений.

### 4. Принять и передать

- `python3 raskraska/test_browser.py --out <evidence>`: Chromium desktop/узкий смартфон/планшет, каталожный переход и самостоятельный файл, выбранная краска/ластик остаются видны, отрисованы и доступны все области, реальные события, ноль JS/сетевых ошибок; осмотреть скриншоты.
- Проверить scope diff, сборку и точные байты приложения, сделать локальный коммит только согласованных файлов (без push). В Telegram приложить само приложение и скриншот. Safari, физический тач и семейный плейтест отдельно, без заявления о проверке.
